# Техническое задание
## Проект: Бэкенд приложения-блога

## 1. Общая информация

Приложение представляет собой блог с веб‑фронтендом на Nginx (готовый фронт предоставлен в виде Docker‑окружения) и разрабатываемым бэкендом на Java с использованием Spring Framework (без Spring Boot).

Фронтенд отправляет REST‑запросы к бэкенду, который работает в сервлет‑контейнере Tomcat или Jetty и использует СУБД (PostgreSQL или H2) для хранения данных постов и комментариев.

## 2. Архитектура системы

### 2.1. Компоненты

- Фронтенд:
    - Статический контент в директории `dist` (`index.html`, JS, CSS). 
    - Конфигурация веб‑сервера в `nginx.conf`. 
    - Docker‑образ фронтенда описан в `Dockerfile`. 
    - Запуск через `docker-compose.yaml`. 

- Бэкенд:
    - Java‑приложение на Spring Framework 6.1+ без Spring Boot. 
    - Запуск в сервлет‑контейнере Tomcat/Jetty. 
    - REST API для фронтенда. 

- База данных:
    - СУБД для хранения постов и комментариев (персистентная PostgreSQL или in‑memory H2). 

### 2.2. Взаимодействие компонентов

- Браузер пользователя обращается к фронтенду по `http://localhost:80/` (или `http://localhost/`). 
- Фронтенд по REST запрашивает данные у бэкенда по `http://localhost:8080/`. 
- Бэкенд выполняет SQL‑запросы к БД для операций CRUD по постам и комментариям. 

## 3. Функциональные требования

### 3.1. Работа с постами

Бэкенд должен поддерживать следующие операции: 

1. Получение списка постов (лента)
    - Метод: `GET /api/posts?search=...&pageNumber=...&pageSize=...` (все параметры обязательны). 
    - Ответ (JSON):
      ```json
      {
        "posts": [
          {
            "id": 1,
            "title": "Название поста 1",
            "text": "Текст поста в формате Markdown...",
            "tags": ["tag_1", "tag_2"],
            "likesCount": 5,
            "commentsCount": 1
          }
        ],
        "hasPrev": true,
        "hasNext": false,
        "lastPage": 3
      }
      ```  

- Особенности:
    - `text` в списке постов, если длина > 128 символов, обрезается до 128 символов с добавлением «…». 
    - `hasPrev` — `true`, если текущая страница не первая. 
    - `hasNext` — `true`, если текущая страница не последняя. 
    - `lastPage` — номер последней страницы. 

2. Получение одного поста
    - Метод: `POST /api/posts/{id}`. 
    - Ответ (JSON):
      ```json
      {
        "id": 1,
        "title": "Название поста 1",
        "text": "Текст поста в формате Markdown...",
        "tags": ["tag_1", "tag_2"],
        "likesCount": 5,
        "commentsCount": 1
      }
      ```  

- Текст `text` не обрезается (полный Markdown). 

3. Добавление поста
    - Метод: `POST /api/posts`. 
    - Запрос (JSON):
      ```json
      {
        "title": "Название поста 3",
        "text": "Текст поста в формате Markdown...",
        "tags": ["tag_1", "tag_2"]
      }
      ```  

- Все поля обязательны. 
- Ответ (JSON):
  ```json
  {
    "id": 3,
    "title": "Название поста 3",
    "text": "Текст поста в формате Markdown...",
    "tags": ["tag_1", "tag_2"],
    "likesCount": 0,
    "commentsCount": 0
  }
  ```  
  `likesCount` и `commentsCount` инициализируются нулём. 

4. Редактирование поста
    - Метод: `PUT /api/posts/{id}`. 
    - Запрос (JSON):
      ```json
      {
        "id": 3,
        "title": "Название поста 3",
        "text": "Текст поста в формате Markdown...",
        "tags": ["tag_1", "tag_2"]
      }
      ```  

- Ответ (JSON) с актуальными `likesCount` и `commentsCount`. 

5. Удаление поста
    - Метод: `DELETE /api/posts/{id}`. 
    - Поведение: удалить пост и все его комментарии, вернуть `200 OK`. 

6. Инкремент лайков поста
    - Метод: `POST /api/posts/{id}/likes`. 
    - Поведение: увеличить число лайков на 1, вернуть обновлённое число лайков в теле ответа. 

7. Обновление картинки поста
    - Метод: `PUT /api/posts/{id}/image`. 
    - Тело запроса: `multipart/form-data` с полем `image` (`filename="image_name.jpg"`). 
    - Поведение: обновить картинку поста, вернуть `200 OK`. 

8. Получение картинки поста
    - Метод: `GET /api/posts/{id}/image`. 
    - Поведение: вернуть массив байт изображения в теле ответа. 

### 3.2. Работа с комментариями

1. Получение списка комментариев поста
    - Метод: `GET /api/posts/{postId}/comments`. 
    - Ответ (JSON):
      ```json
      [
        { "id": 1, "text": "Комментарий к посту 1", "postId": 1 },
        { "id": 2, "text": "Ещё один комментарий к посту 1", "postId": 1 }
      ]
      ```  


2. Получение одного комментария
    - Метод: `GET /api/posts/{postId}/comments/{id}`. 
    - Ответ (JSON) с полями `id`, `text`, `postId`. 

3. Добавление комментария
    - Метод: `POST /api/posts/{postId}/comments`. 
    - Запрос (JSON):
      ```json
      {
        "text": "Комментарий к посту",
        "postId": 1
      }
      ```  

- Ответ (JSON) с сгенерированным `id`. 

4. Редактирование комментария
    - Метод: `PUT /api/posts/{postId}/comments/{id}`. 
    - Запрос и ответ (JSON) с полями `id`, `text`, `postId`. 

5. Удаление комментария
    - Метод: `DELETE /api/posts/{postId}/comments/{id}`. 
    - Поведение: удалить комментарий, вернуть `200 OK`. 

### 3.3. Логика поиска и пагинации (на стороне бэкенда)

Поисковая строка и фильтры должны поддерживать следующую логику: 

- Строка поиска разбивается на слова по пробелам, пустые слова отбрасываются. 
- Слова, начинающиеся с `#`, трактуются как теги, посты фильтруются по наличию всех указанных тегов (логическое «И»). 
- Остальные слова склеиваются в подстроку, которая используется для поиска по названию поста. 
- Фильтрация по подстроке и тегам также происходит по «И». 
- Пагинация организована через параметры `pageNumber` и `pageSize`, с флагами `hasPrev`, `hasNext` и `lastPage` в ответе. 

## 4. Нефункциональные требования

- Язык разработки: Java 21. 
- Фреймворк: Spring Framework 6.1+ (без Spring Boot). 
- Сервлет‑контейнер: Tomcat или Jetty. 
- Сборка: Maven или Gradle. 
- БД: PostgreSQL (персистентная) или H2 (in‑memory). 
- Адрес бэкенда: `http://localhost:8080`. 

## 5. Структура проекта и слои

- Слои приложения:
    - Controller (REST‑эндпоинты). 
    - Service (бизнес‑логика). 
    - DAO/Repository (доступ к данным). 
    - Model/Entity (доменные сущности: пост, комментарий). 

- Требования к коду:
    - Соблюдение принципов SOLID, YAGNI и других принятых практик корпоративной разработки. 
    - Грамотное наименование классов, методов, полей по назначению. 

## 6. Требования к БД

- Хранить сущности:
    - Посты (id, title, text, tags, likesCount и др.). 
    - Комментарии (id, text, postId и др.). 
- Предусмотреть SQL‑скрипты для создания схемы БД при старте приложения. 

## 7. Инфраструктура и деплой

- Проект собирается в `war` для развёртывания в сервлет‑контейнере. 
- Необходимы:
    - настройки сборки `war` в Maven/Gradle;
    - `web.xml`;
    - Java‑конфигурации для интеграции со Spring и выбранной СУБД. 

## 8. Тестирование

- Используемые инструменты:
    - JUnit 5;
    - Spring TestContext Framework;
    - WebMvc;
    - H2 для интеграционных тестов. 

- Требования:
    - Юнит‑тесты для сервисного слоя и модели. 
    - Интеграционные тесты MVC и DAO для типовых сценариев (создание поста, удаление, фильтрация, работа с комментариями и т. п.). 
    - Максимальное использование кеширования контекста для ускорения тестов. 
    - Все тесты должны проходить успешно («зелёные»).
